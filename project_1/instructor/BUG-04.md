# BUG 04: Duplicate Student ID Allowed During Creation

## Bug Title
Duplicate Student ID Can Be Created Without Error

## Location
- Backend Service: `src/main/java/com/sms/service/StudentServiceImpl.java` (`createStudent` method)
- Backend Entity: `src/main/java/com/sms/entity/Student.java` (`studentId` column definition)

## How to Reproduce
1. In the application, find an existing student ID (e.g. `STU1001` for Alice Johnson).
2. Click **Register New Student**.
3. Enter `STU1001` in the **Student ID** field.
4. Enter different name and email (e.g. "Alice Clone", `alice.clone@university.edu`).
5. Fill remaining required fields and click **Save Student**.
6. The student is created successfully with HTTP 201 Created.
7. Check the student table: Two different student records now share the identical Student ID `STU1001`!

## Expected Behavior
The Student ID must be unique across the entire institution. Attempting to create or register a student with an existing Student ID must be rejected with HTTP 409 Conflict: `"Student with ID STU1001 already exists"`.

## Actual Behavior
Duplicate student IDs are freely saved without any error.

## Root Cause
In `StudentServiceImpl.java`:
```java
@Override
@Transactional
public StudentResponseDto createStudent(StudentRequestDto request) {
    // Check for duplicate student ID
    if (request.getId() != null && studentRepository.existsByStudentId(request.getStudentId())) {
        throw new DuplicateResourceException("Student with ID " + request.getStudentId() + " already exists");
    }
    ...
```
When creating a new student via `POST /api/students`, `request.getId()` is `null` (since IDs are generated by the database upon insertion). Because `request.getId() != null` is `false`, the entire condition evaluates to `false`, and `studentRepository.existsByStudentId(...)` is never evaluated!

Furthermore, in `Student.java`:
```java
@Column(name = "student_id", nullable = false, length = 30)
private String studentId;
```
The database column lacks `unique = true`, so the database constraint does not reject the insert either.

## Incorrect Code Explanation
The developer erroneously assumed that checking `request.getId() != null` was needed to distinguish updates, or mistakenly checked `getId()` instead of checking `getStudentId() != null`.

## Correct Solution
1. **In `StudentServiceImpl.java`**:
   ```java
   @Override
   @Transactional
   public StudentResponseDto createStudent(StudentRequestDto request) {
       if (studentRepository.existsByStudentId(request.getStudentId().trim())) {
           throw new DuplicateResourceException("Student with ID " + request.getStudentId() + " already exists");
       }
       ...
   ```
2. **In `Student.java`**:
   ```java
   @Column(name = "student_id", nullable = false, unique = true, length = 30)
   private String studentId;
   ```

## Why the Solution Works
1. The service layer actively queries `existsByStudentId` unconditionally during creation.
2. The database entity level enforces a unique index on `student_id`, providing defense-in-depth against race conditions.
